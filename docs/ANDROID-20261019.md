# Führerschein Viet-Duc — Android

Android reuses the tested iOS public source on branch `codex/ios-public-20261016`, base commit `10b0ebf0dec3ac4b893447f310b902e997e6936d`. The latest iOS upload used `51bbcdaecdfcafa2066741143b7e80c373f8ee80` in run `39033000383`; the later base commit records that result. AI, Speed Room and all existing learning features are preserved.

The generator copies the committed, bundled iOS `www` without rebuilding or rewriting the app's React/AI/Speed Room code. Android adds its own stable device identity before startup, uses the existing Capacitor 8.4 runtime and native HTTP implementation, and lets Capacitor handle native system-bar insets. Phone orientation remains portrait, tablets may rotate. Only Internet permission is needed. Backup is disabled. No production accounts, passwords or signing private keys are stored in GitHub.

## Reproduce the preview build

Run the Android workflow on this branch. Its source checks run the existing feature test suite and TypeScript/Vite checks. It installs pinned `@capacitor/android@8.4.0` without changing the committed lockfile, generates the Android host and copies icons from the existing brand assets. Generated Android files stay in the runner's checkout. The original Xcode project and bundle are not altered in git.

`Führerschein-Viet-Duc-Android-v1.0.0-preview1.apk` is an installable debug preview with package `com.ronnguyen.fuehrerscheinvietduc.preview`. Each independently signed preview may need a clean installation. Synced learning data stays on the existing backend. The release AAB uses `com.ronnguyen.fuehrerscheinvietduc` and must be signed with the owner's Android upload key before Play Console upload. Private signing materials are retained separately from this public repository.

Moving from the iOS app to Android creates a new device identity. Use a permitted test account or the existing admin device-reset function if the backend rejects an already-bound student. Do not bypass the device lock or reset all students.

## Review on a real Android device

Test login and session retention, learning/topics/wrong answers/bookmarks, video/image questions, mock exams, account deletion with a disposable test account, AI entitlements/chat and Speed Room lobby/play/chat. Native HTTP and Android layout require a real-device pass even after emulator smoke checks.

## Google Play

A signed bundle is a build artifact, not a published app. Complete account identity/phone verification, app listing/images, Data safety (including AI chat and Speed Room messages), reviewer access and account deletion disclosures. A new personal account must satisfy closed testing and receive production access before the app can be released publicly.
